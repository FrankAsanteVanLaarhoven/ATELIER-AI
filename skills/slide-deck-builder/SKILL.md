# Slide Deck Builder

## Workflow
1. Identify audience, decision, time limit and desired action.
2. Build a one-sentence narrative spine.
3. Create a storyboard before slide prose.
4. For every factual claim, attach a source reference before design.
5. Choose one message per slide; remove paragraphs that do not change a decision.
6. Use the provided design system. If none exists, use restrained enterprise typography, spacing and hierarchy rather than decorative AI styling.
7. Prefer diagrams, tables and charts only when they communicate structure or evidence better than text.
8. Run the checks below before release.

## Required slide checks
- Title states the point, not just the topic.
- No unsupported number or factual claim.
- Visual hierarchy is readable at presentation distance.
- Consistent grid, typography and component rules.
- No fake logos, citations, customer claims or generated data.
- Appendix contains technical detail that would overload the core narrative.

## Common structures
Executive decision deck: context → evidence → options/tradeoffs → recommendation requested from audience → implementation → risk → KPI.
Technical architecture deck: problem → requirements → architecture → control flow → failure modes → evals → benchmark → deployment → risks.
Training deck: objective → concept → worked example → failure case → practice → answer/reasoning → summary.
